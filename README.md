# cloud-stroage

瑞锦云存储项目源码归档，按本地已确认的历次更新整理，截止 **2026-10-23**。仓库名沿用 `cloud-stroage`。

这是现有 PHP + MySQL 站点的源码，不含线上用户文件、账号数据、密码、邮件授权码或服务器配置。此次同步 GitHub 不会部署或修改线上站点。

## 已纳入功能

- 模块化入口、独立 PHP 处理模块、视图、CSS 和 JavaScript。
- 用户目录隔离，超级管理员/管理员/普通用户权限，账号管理和修改密码。
- CSRF、统一 Session、POST 退出、改密后的会话校验。
- 文件上传、下载、预览、移动、目录管理、下载密码和分享管理。
- 分享路径校验、取消分享提示、搜索框自动填充修复。
- 文件分页（30/50/100）、文件名/拼音搜索缓存、图片/视频缩略图缓存。
- A/C 两种主题、移动端布局修复、最后登录时间。
- 邮箱注册、绑定、找回密码、验证码倒计时、限流和占用提示、邮件后台队列。
- 最新同名上传提示及拒绝覆盖；按修改时间/大小排序，并保留搜索和分页条件。

## 配置与部署边界

**已有服务器：保留原 `db_config.php`、站点外邮件配置、用户 `data/` 以及文件元数据。不要用仓库覆盖这些运行数据。** 本次只是上传源码，没有运行任何数据库迁移。

新部署时，先确认 PHP 扩展和 MySQL 结构，再使用空白示例自行配置；不要把填写后的文件提交 Git。示例可从 `CLOUD_STORAGE_DB_*` 环境变量读取数据库连接，PHP-FPM 与 CLI 是否都能获取这些变量需由部署方确认。邮件配置仍按代码约定放在站点目录外，默认 `/etc/cloud-storage/mail.php`，也支持 `CLOUD_STORAGE_MAIL_CONFIG`。

### 初始化结构缺失

原目录没有找到 `init_db.sql`，本仓库**没有伪造或从生产导出 users 表初始化脚本**。因此不是已经验证的“一键全新安装包”。新部署需要另行准备与现有代码兼容的 users 基础表结构；不能把 `tests/fixtures/schema.sql` 当作生产 SQL（它仅用于内存 SQLite 测试）。

保留的既有 `migrate_last_login.php`、`cli/migrate_email_recovery.php` 只负责增量结构，不负责完整建站。本次没有修改或执行它们。执行迁移前必须先备份数据库并确认影响；MySQL DDL 不能整体事务回滚，回退应用时可保留新增列/表，必要时从已验证备份恢复，不要直接删除已有数据。

### 运行条件

- PHP + PDO MySQL；邮箱功能依赖 OpenSSL，部分字符串处理依赖 mbstring。
- 图片缩略图依赖相应图像扩展，视频缩略图依赖服务器 FFmpeg；本次没有安装或配置服务器软件。
- 同名上传并发保护使用 PHP `link()`，PHP-FPM 和存储文件系统需支持硬链接；不支持时明确报保存失败，不回退覆盖原文件。
- 用户根目录/“全部文件”仍使用原有自动分类规则；查重按实际目标目录和清洗后的文件名判断，不是文件内容去重。
- 时间排序使用文件最后修改时间；文件夹置顶，不递归计算目录大小。
- 既有页面仍使用外部前端 CDN；此次未改成离线资源。
- Web 服务必须限制用户数据、隐藏元数据、配置、测试、CLI、文档等非公开目录/文件的直接访问；仓库忽略规则不是 Web 访问控制。
